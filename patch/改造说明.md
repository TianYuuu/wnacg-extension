# 绅士漫画（WNACG）源改造说明

> 目标：让「排行（今日 / 本周 / 本月 / 今年）+ 分类（单行本、杂志…）」能像网页上一样自由组合，而不是一选分类就掉回「最近更新」。

## 交付物

| 文件 | 说明 |
| --- | --- |
| `wnacg-v1.6.101-replace.apk` | **替换版**：包名与源名跟官方完全一致（源 id 相同，收藏无缝沿用），已自签名，可装到所有 Tachiyomi 系客户端 |
| `wnacg-custom.jks` | 上面 APK 使用的签名密钥（alias `wnacgkey`，storepass / keypass 均为 `wnacg123`）。以后自己重新构建要沿用这个 key，否则只能卸载重装 |
| `wnacg.diff` | 相对 `keiyoushi/extensions-source` 的补丁（含 `build.gradle.kts` 的包名改动），`git apply` 即用 |
| `WNACG.kt` / `Filters.kt` / `Preferences.kt` / `build.gradle.kts` | 改好的完整文件，也可直接覆盖 |
| `orig/` | 四个文件的原始版本，方便对照 |

> 密钥只用于这个自建扩展，别拿去签别的东西。想换回"替换官方扩展"的形态，把 `build.gradle.kts` 里的 `pkgName` 那行删掉即可（包名会回到 `…zh.wnacg`）。

## 一、结论：改扩展，不改 Komikku

**这个需求的正确改造点是扩展（keiyoushi 的 wnacg 源），不是 Komikku 本体。** 原因是 Mihon / Komikku 这一套扩展架构的分工：

| 环节 | 由谁决定 | 代码位置 |
| --- | --- | --- |
| 筛选面板里有哪些选项、每个选项什么含义 | **扩展** 的 `getFilterList()` | `WNACG.kt` |
| 应用把筛选结果原样传回扩展 | 应用 | 应用只做 UI |
| 「热门」标签页发起请求 | `getPopularManga(page)` —— **签名里没有 filters** | `WNACG.kt` |
| 「最近更新」标签页发起请求 | `getLatestUpdates(page)` —— **签名里也没有 filters** | `WNACG.kt` |
| 点「筛选」→ 确定 | 切到搜索模式，调 `getSearchMangaList(page, query="", filters)` | `BrowseSourceScreenModel.kt` |
| 从「筛选结果」切回「热门 / 最近更新」 | `resetFilters()` —— **筛选被清空** | `BrowseSourceScreen.kt` |

也就是说：**「热门」标签页在应用层面根本没有接收筛选条件的位置**——不是 Komikku 写坏了，而是扩展 API 就是这么设计的（`getPopularManga(page: Int)`）。

要"在热门标签里筛分类"，得改扩展接口 + 改三个应用 + 让所有源适配，代价完全不成比例。而「点筛选 → 选榜单 + 选分类」这条链路应用是支持的，只是原扩展没把 URL 拼对。

## 二、真正的 bug：URL 拼错了

原扩展（`WNACG.kt`）里只有两种列表 URL：

```kotlin
// 热门：写死周榜，永远不带分类
private fun popularMangaUrl(page: Int) = "$baseUrl/albums-favorite_ranking-page-$page-type-week.html"
// 最新
private fun latestUpdatesUrl(page: Int) = "$baseUrl/albums-index-page-$page.html"
```

而 `Filters.kt` 里所有分类的 URI 模板全是 `albums-index-page-%d-cate-XX.html`，**也就是"最新 + 分类"**。于是：

> 空白关键词 + 选分类 → 拼出 `albums-index-page-1-cate-6.html` → 「热门」自然就变成「最近更新」了。

**站点其实是支持"排行 + 分类"的**，只是这个组合 URL 没人拼出来。我实测过全部组合（HTTP 200，标题正确）：

| URL | 页面标题 |
| --- | --- |
| `/albums-favorite_ranking-page-1-type-day.html` | 今日 · 收藏排行榜 · 全部分类 |
| `/albums-favorite_ranking-page-1-type-week-cate-6.html` | **單行本 · 本週 · 收藏排行榜** |
| `/albums-favorite_ranking-page-1-type-month-cate-9.html` | **單行本／漢化 · 本月 · 收藏排行榜** |
| `/albums-favorite_ranking-page-1-type-year-cate-6.html` | **單行本 · 本年 · 收藏排行榜** |

规律（`cate` 段可省略，省略即全部分类）：

```
/albums-favorite_ranking-page-{页码}-type-{day|week|month|year}[-cate-{分类ID}].html
/albums-index-page-{页码}[-cate-{分类ID}].html        ← 最近更新
```

顺带确认的两件事：

1. **排行页的 HTML 结构和"最新"列表完全一致**（`li.gallary_item`、`.title > a`、`span.thispage` 分页），所以解析代码一行都不用改 —— 这也是这个改造风险很低的原因。
2. **排行不支持标签**：`...-type-day-tag-漢化.html` 返回 200 但标签被忽略。所以标签只能配合"最近更新"用。

原扩展还有两个小毛病一并修掉：`杂志&短篇-汉语` 重复了两次（cate-7 / cate-10）；缺了站点新增的 `韩漫-合集`（cate-38）。

## 三、改造后的效果

| 你想做的事 | 操作 | 实际请求 |
| --- | --- | --- |
| 只想看某个周期的排行 | 直接看「热门」标签（周期=设置里的「热门页榜单」，默认本周） | `type-{热门页榜单}` |
| 周榜 + 单行本 | 浏览 → 筛选 → 榜单=本周排行、分类=单行本 → 确定 | `type-week-cate-6` |
| 本月榜 + 单行本-汉化 | 同上 | `type-month-cate-9` |
| 今年榜 + 全部分类 | 榜单=今年排行，分类=全部分类 | `type-year` |
| 单纯按分类看最新 | 榜单=最近更新 + 分类 | `albums-index-page-N-cate-X` |
| 按标签看 | 标签框填词（忽略榜单/分类） | `albums-index-page-N-tag-X` |
| **关键词搜索 + 周期排序** | 搜索框输入 + 榜单=今日/本周/本月/今年 | `?s=heat_{day\|week\|month\|year}_DESC&q=…` |
| 关键词搜索（默认） | 只输入关键词（榜单=设置里的筛选默认，默认今年） | `?s=heat_year_DESC&q=…` |
| 搜索 + 分类 | 搜索框输入 + 分类=单行本 | `?q=…&cate=6` |
| 搜索 + 多标签（A 且 B） | 标签填 `漢化 巨乳` | `?q=…&tag=漢化,巨乳` |
| 搜索 + 分类 + 多标签 + 周期 | 全部叠加 | `?q=…&cate=6&tag=漢化,巨乳&s=heat_month_DESC` |

**唯一无法完全满足的**：热门标签页里同时筛分类。这是应用层限制（见第一节）。两个实用替代：

- 用「筛选」面板 —— 效果等价，只是标题变成搜索态；
- 用 Komikku 的**保存搜索**：把「本月排行 + 单行本」存下来，下次一键进入，比每次点筛选快得多。

## 四、改动清单（共 4 个文件）

### 1. `Filters.kt`（整体替换）

```kotlin
class RankingFilter : Filter.Select<String>(
    "榜单",
    arrayOf("最近更新", "今日排行", "本周排行", "本月排行", "今年排行"),
) {
    val type: String get() = RANKING_TYPES[state]   // "" / day / week / month / year
}

class CategoryFilter : Filter.Select<String>("分类", CATEGORIES.map { it.first }.toTypedArray()) {
    val cateId: Int get() = CATEGORIES[state].second   // -1 = 全部分类
}
```

分类直接存站点 `cate` 编号（不再是整段 URI 模板），这样才能和榜单自由拼接。

### 2. `WNACG.kt`（三处）

```kotlin
private fun listUrl(page: Int, type: String, cateId: Int): String {
    val cate = if (cateId >= 0) "-cate-$cateId" else ""
    return if (type.isEmpty()) {
        "$baseUrl/albums-index-page-$page$cate.html"
    } else {
        "$baseUrl/albums-favorite_ranking-page-$page-type-$type$cate.html"
    }
}

override fun getFilterList(data: JsonElement?) = FilterList(
    Filter.Header("榜单与分类可自由组合，仅在「筛选」中生效"),
    RankingFilter(),
    CategoryFilter(),
    Filter.Separator(),
    Filter.Header("标签只支持最近更新，且与分类互斥"),
    TagFilter(),
)

// 热门标签页的周期改为读设置
private fun popularMangaUrl(page: Int) = listUrl(page, preferences.hotRankingType, NO_CATE)
```

`searchMangaUrl` 里空关键词的分支改成：标签优先 → 否则用 `listUrl(page, 榜单, 分类)`。

### 3. `Preferences.kt`（新增一项设置）

```kotlin
ListPreference(context).apply {
    key = HOT_RANKING_TYPE_PREF
    title = "热门页榜单周期"
    entries = arrayOf("今日排行", "本周排行", "本月排行", "今年排行")
    entryValues = arrayOf("day", "week", "month", "year")
    setDefaultValue("week")
}
```

> 为什么要这个设置：热门标签页拿不到筛选条件，只能靠设置改变它的周期。默认仍是「本周」，和原行为一致，不想要可以删掉这块。

## 五、装到手机上

### 方案 A：本地构建（最省事，已在本机跑通）

```bash
git clone --depth 1 https://github.com/keiyoushi/extensions-source.git
cd extensions-source
git apply /path/to/wnacg.diff          # 本目录的 wnacg.diff

echo "sdk.dir=$HOME/Library/Android/sdk" > local.properties

# 自签名（扩展必须签名才能装）。想沿用当前 APK 的签名，改成 cp 本目录的 wnacg-custom.jks signingkey.jks
keytool -genkeypair -keystore signingkey.jks -alias wnacgkey \
        -keyalg RSA -keysize 2048 -validity 10000 \
        -storepass wnacg123 -keypass wnacg123 -dname "CN=wnacg"

export ALIAS=wnacgkey KEY_STORE_PASSWORD=wnacg123 KEY_PASSWORD=wnacg123
./gradlew :src:zh:wnacg:assembleRelease
# 产物：src/zh/wnacg/build/outputs/apk/release/tachiyomi-zh.wnacg-v1.6.101.apk
```

把 APK 传到手机安装即可。**本目录的 `wnacg-v1.6.101-replace.apk` 就是这条命令的产物**，不用再自己跑一遍。

### 为什么能替换官方扩展（收藏不失联）

Tachiyomi 系的源 id 不是包名，而是用**源名 + 语言 + versionId** 算出来的（`build-logic` 里的 `computeSourceId`）：

```kotlin
val key = "${name.lowercase()}/$lang/$versionId"
MD5(key) 取前 8 字节 → Long
```

官方值的实测结果（从 keiyoushi 的 `index.pb` 里解析出来）：

```
pkg   eu.kanade.tachiyomi.extension.zh.wnacg
源名  紳士漫畫   lang zh   versionId 1
id    6551136894818591762
```

只要 `build.gradle.kts` 里保持 `name = "WNACG"`、`source { name = "紳士漫畫"; lang = "zh" }`，算出来的 id 就是同一个数，
**库里的收藏、阅读记录、章节进度全部原样指向这个版本**，不需要迁移。

```kotlin
keiyoushi {
    name = "WNACG"          // 扩展列表里显示的名字
    pkgName = "zh.wnacg"    // 与官方同包名 → 不能共存，必须替换
    versionCode = 100       // 106100，官方当前 106002
    ...
    source {
        name = "紳士漫畫"    // 这一行决定源 id，千万别改
        lang = "zh"
        baseUrl = "https://www.wn07.cfd"
    }
}
```

代价：**同包名 + 不同签名，必须先卸载官方扩展**才能装（Android 规则）。卸载扩展不影响漫画库数据。

### 方案 B：fork + GitHub Actions

`build_push.yml` 里上传产物那一步写死了 `if: github.repository == 'keiyoushi/extensions-source'`，签名 key 也来自官方 secrets。fork 后要自己删掉这个 if、加上自己的 keystore secret 才能从 Actions 下载 APK —— 步骤比方案 A 还多，只在你想长期自动构建时才有意义。

### 方案 C：PR 回上游

改动能过 ktlint/spotless 就有机会被合并，好处是以后跟着官方一起更新，坏处是"热门页周期设置"这类个人偏好容易被维护者砍掉（上游倾向保持源简单）。

### 方案 D（可选）：多源化

把这个扩展改成多源，今日/本周/本月/今年各做一个源条目。好处是每个源点进去的「热门」标签就是那个榜；代价是源列表里多 4 个条目，而且**已保存的搜索是跟着源走的**，5 个源就要建 5 套 chip，反而更累。除非你只在源列表里挑榜单、不打算用 chip，否则不推荐。

## 六、界面怎么设计（把榜单/分类搬到最上面那一行）

### 先认清一个硬约束

顶部那排 chips 是 Komikku 硬编码的，扩展只能提供「热门」「最近更新」两条数据，加不了新按钮：

```kotlin
// BrowseSourceScreen.kt:252-317
FilterChip(selected = state.listing == Listing.Popular, ...)   // 热门
FilterChip(selected = state.listing == Listing.Latest, ...)    // 最近更新
FilterChip(onClick = screenModel::openFilterSheet, ...)        // 筛选
```

但紧接着的 `318-334` 行有一个关键机制：

```kotlin
state.savedSearches.forEach { savedSearch ->
    FilterChip(onClick = { screenModel.onSavedSearch(savedSearch) { ... } }, label = { Text(savedSearch.name) })
}
```

**「已保存的搜索」会被渲染成同一行的 chips。** 这就是把榜单/分类搬到顶部的唯一入口 —— 不需要改 App。

### 目标界面

顶部一行变成（可横向滚动）：

```
[热门] [最近更新] [筛选] │ [★今日] [★本周] [★本月] [★今年] [★单行本] [★本周·汉化] …
```

- 点 `★本周` → 本周榜
- 点 `★本周·汉化` → 本周榜 ∩ 单行本-汉化
- 点 `热门 / 最近更新` → 原行为（周期由扩展设置决定）

一共 1 次点击，比现在的「筛选 → 选榜单 → 选分类 → 确定」少 3 步。

### 怎么建（每枚 chip 约 5 秒）

1. 进入「紳士漫畫+」，点顶部「筛选」；
2. 选好「榜单」和「分类」（想更窄可以再填标签）；
3. 点对话框**右上角的保存图标** → 命名（建议带 ★ 前缀方便一眼认出）→ 保存。

建完立刻出现在顶部和筛选面板里；长按 chip 可以删除。建议先建这几枚：

| chip 名 | 榜单 | 分类 | 用途 |
| --- | --- | --- | --- |
| ★今日 | 今日排行 | 全部分类 | 看今天最热 |
| ★本周 | 本周排行 | 全部分类 | 默认常用 |
| ★本月 | 本月排行 | 全部分类 | 月度回顾 |
| ★今年 | 今年排行 | 全部分类 | 年度神作 |
| ★本周·单行本 | 本周排行 | 单行本 | 只看单行本 |
| ★本月·汉化 | 本月排行 | 单行本-汉化 | 只看汉化 |

### 这套设计的边界（说清楚，免得白折腾）

1. **chip 是「组合快照」，不是两行独立选择器。** 想要"任意榜单 × 任意分类"的二维组合，还是得进筛选面板 —— 应用没有提供第二行 chips 的位置。实际用下来，人真正需要的组合就那么几个，6~8 枚 chip 足够。
2. **筛选结构变了，旧 chip 会失效。** 保存搜索按筛选器的索引/值序列化。1.6.9 起榜单从 6 项减为 5 项（去掉了「跟随默认」），索引整体前移一位，**旧 chip 会指向错误周期或直接报"无效"，请装 1.6.9 及以后版本全部删掉重建**。
3. **chip 跟着源走。** 官方「紳士漫畫」里也能建 chip，但它的筛选表达不了"榜单+分类"，所以只有改造版能建带榜单的。
4. 点 chip 后顶部会进入搜索态（列表照常显示，只是 toolbar 少了个标题），这是 Komikku 对保存搜索的既定表现，不影响使用。
5. **chip 只有 Komikku 系有**（SY 分支功能），Mihon / TachiManga 没有「保存」按钮。跨客户端要用的通用能力看第八节。

### 真要「两行独立 chips」怎么办

只能改 Komikku 本体：在 `BrowseSourceScreen` 里加一段，把 `Filter.Select` 类型的筛选项渲染成 chips，并让点击后触发一次空关键词搜索。代价是：

- 要自己编译 Komikku（Gradle + Android SDK），产出的是一个你自己的 App；
- 签名和官方不同，**装它必须先卸载官方 Komikku**，漫画库要导出/导入备份；
- 以后官方每次更新你都得重新合并、重编。

所以我的建议是先用「保存搜索 chips」这套，它能覆盖 90% 的场景；如果用了两周还是嫌 chip 太多，再考虑 fork App。

## 七、搜索也支持「今日/本周/本月/今年」

一开始我以为站点搜索只能按时间排 —— 因为搜索表单里 `s` 是写死的隐藏字段：

```html
<input type="hidden" name="s" value="create_time_DESC">
```

但从页面上的「最新 / 今日 / 本週 / 本月 / 今年」这一排链接（HTML 里被转义成 `&amp;s=`，容易漏看）可以拿到全部取值，实测 5 个都有效、结果确实不同（以关键词「人妻」为例，首条结果各不相同）：

| 选项 | `s` 参数 |
| --- | --- |
| 最新 | `create_time_DESC` |
| 今日 | `heat_day_DESC` |
| 本周 | `heat_week_DESC` |
| 本月 | `heat_month_DESC` |
| 今年 | `heat_year_DESC` |

所以在 1.6.4 里，**「榜单」这一个筛选同时作用于列表和关键词搜索**：

```kotlin
val sort = when (type) {
    "day" -> "heat_day_DESC"
    "week" -> "heat_week_DESC"
    "month" -> "heat_month_DESC"
    "year" -> "heat_year_DESC"
    else -> "create_time_DESC" // 最近更新
}
```

用法：搜索框输入「人妻」+ 榜单选「本月排行」→ 结果是本月热度的人妻作品。

### 两个默认值，但筛选里不出现「跟随默认」（1.6.9）

1.6.9 之前筛选的「榜单」第一项是「跟随默认」，它内部再分浏览/搜索两个默认值。问题是**下拉框显示的是"跟随默认"，你没法一眼知道它到底会走哪个周期**。这一版把它去掉了：榜单只剩 5 个具体选项，选中项由设置直接决定初始值。

| 设置项 | 默认值 | 作用 |
| --- | --- | --- |
| 热门页榜单 | **本周排行** | 点进源时「热门」标签的周期（走 `getPopularManga`，与筛选无关） |
| 筛选面板默认榜单 | **今年排行** | 打开「筛选」时「榜单」默认选中的那一项；搜索关键词也按它排序 |

所以：

- 点进源 → 热门 = 本周榜（`...-type-week`）；
- 搜索框输入「人妻」→ `s=heat_year_DESC`，今年最热，不用点任何东西；
- 打开「筛选」，**榜单那一栏明明白白写着"今年排行"**，你可以直接改成别的周期，不会再有"这到底是哪个默认"的疑问；
- 只改分类不改榜单时，浏览用的就是下拉框里显示的那个周期 —— 显示什么就是什么，没有隐藏映射。

代价（如实说）：榜单默认值对"浏览"和"搜索"只能有一个，因为 App 给浏览和搜索的是同一个筛选面板。既然你希望搜索默认今年，那浏览时点筛选也会从"今年"起步。想浏览时按本周排，在筛选里选一次本周即可（或把「筛选面板默认榜单」改成本周，搜索就跟着变本周）。

改法：设置 → 扩展 → 紳士漫畫+ → 上面两项各自选。

### 搜索里也能用分类和多标签（1.6.8）

之前我以为"搜索+分类"做不到，理由是在分页链接里看到 `c=a~0~<会话ID>~<序号>` 这种带状态的串。**那个判断是错的** —— 搜索页「篩選」按钮的 JS 里写得很清楚，它直接拼的是普通参数：

```js
add('cate', on.join(','));   add('xcate', off.join(','));
add('u', ...);               add('xu', ...);
add('tag',  ...);            add('xtag', ...);
```

标签输入框的提示也写明了语义：「完整標籤，多個用空格或逗號隔開（**要同時有**）」—— 就是 AND。实测：

| 场景 | URL | 结果 |
| --- | --- | --- |
| 关键词 + 分类=单行本 | `q=人妻&cate=6` | ✅ 工作 |
| 关键词 + 双标签（AND） | `q=人妻&tag=漢化,巨乳` | ✅ 有效（比单标签更窄） |
| 三者叠加 | `q=人妻&cate=6&tag=漢化,巨乳` | ✅ 24 条 → **7 条** |
| 空关键词 + 分类/标签 | `q=&cate=6` | ❌ 0 条，搜索接口必须先有关键词 |
| 无关键词的多标签 | 列表页 `-tag-X` | ❌ 列表页只认一个标签 |

所以现在的用法：

- **多标签搜索**：标签框填 `漢化 巨乳` 或 `漢化,巨乳`，搜出来的必须两个标签都有；
- **搜索内筛分类**：分类选「单行本」，再搜关键词，就只在这个分类里搜 —— 不用"先搜再筛"两步；
- 两者可以再叠加榜单周期（今日/本周/本月/今年）。

代码上就是三个 query 参数：

```kotlin
.addQueryParameter("s", sort)                       // 榜单周期
.apply { if (cateId >= 0) addQueryParameter("cate", cateId.toString()) }
.apply { if (tags.isNotEmpty()) addQueryParameter("tag", tags.joinToString(",")) }
```

还发现站点支持 `xcate`（排除分类）、`xtag`（排除标签）、`u`/`xu`（只看/屏蔽投稿者），需要的话可以再接。

## 八、跨客户端兼容（Komikku / Mihon / TachiManga）

「保存搜索」是 Komikku（继承 TachiyomiSY）才有的功能，Mihon 和闭源分支不一定有，所以它不能当通用方案。各项能力的可移植性：

| 能力 | 靠什么实现 | Komikku | Mihon | TachiManga |
| --- | --- | --- | --- | --- |
| 榜单/分类筛选 | 扩展 `getFilterList()` | ✅ | ✅ | ✅（同系客户端都实现） |
| 搜索默认今年 | 扩展设置 `ConfigurableSource` | ✅ | ✅ | 大概率 ✅（装上看一眼即知） |
| 榜单+分类一键 chip | 应用的「保存搜索」 | ✅ | ❌ | ❌ |
| 榜单作为顶层入口 | 多源化（一个榜一个源） | ✅ | ✅ | ✅ |

结论：

1. **日常主力用「扩展设置 + 筛选」** —— 这是三端都通的组合，1.6.9 的默认状态：热门出本周榜，搜索出今年最热。
2. **chip 只在 Komikku 上用**，当快捷方式，不依赖它。换客户端时行为不会变差，只是少了几个捷径。
3. 如果你确实想在 Mihon / TachiManga 上也做到"榜单是顶层入口、点一下就进"，唯一通用手段是**多源化**：今日/本周/本月/今年各做一个源条目（每个源的「热门」就是那个榜，搜索也用那个周期）。代价是源列表多 3 个条目，而且**全局搜索/迁移时同一作品会出现 4 份**。要的话我可以出一个多源版本给你并存测试，但它和「筛选面板默认榜单」设置会打架（多源版本里每个源固定周期），需要取舍。

## 九、装完没生效？按这个顺序查

1. **先看版本号**：设置 → 扩展 → 紳士漫畫（WNACG）→ 第一项标题必须显示「网址 · **扩展 v1.6.101**」。
   - 不是这个版本 → APK 没覆盖成功（对比一下安装器有没有报错），或者装上的还是官方那个 WNACG（版本号 1.6.2）。
2. **必须彻底退出应用再重开**（从最近任务里划掉，或重启手机）。
   扩展的 dex 在应用启动时加载，覆盖安装后不重启，应用跑的还是旧代码 —— 这是「设置里只有一项、搜索还是没变」最常见的原因，1.6.5 就是这么被误判的。
3. 重开后设置里应有 **两项**，且在「网址」下面：
   - 热门页榜单 → 本周排行
   - 筛选面板默认榜单 → 今年排行
4. **别用旧 chip 验证**：保存搜索会带出它自己存的榜单，会覆盖默认值，那是预期行为，不是 bug。

### Mihon 里搜索结果排序不对？看筛选面板第一行

1.6.100 起，筛选面板顶部多了一行自检：

```
上次搜索实际请求：榜单=今年排行，s=heat_year_DESC
```

这是扩展**真正发出去**的 `s` 参数（每次搜索第一页时记录，存在扩展自己的设置里）。判定方法：

| 显示内容 | 含义 | 处理 |
| --- | --- | --- |
| `榜单=今年排行，s=heat_year_DESC` | 请求是对的 | 结果差异来自站点的「本年」= 本年内累计热度，会包含往年发布的作品，不是按发布日期筛；也可能你搜的是「全局搜索」把多源结果混在一起了 |
| `榜单=最近更新，s=create_time_DESC` | 客户端传进来的筛选状态是「最近更新」 | 在筛选面板里手动选成「今年排行」；或该客户端的浏览页缓存了旧筛选状态，退出该源重进 |
| `无榜单筛选器 → 用设置默认` | 客户端没传筛选器（如全局搜索 / 多源搜索），用的是设置里的「筛选面板默认榜单」 | 看设置里那一项是不是今年 |

同时注意确认来源名：官方「紳士漫畫」的搜索固定是 `create_time_DESC`（最新发布），只有「紳士漫畫+」才有周期排序。

仓库：<https://github.com/TianYuuu/wnacg-extension>（public，两个分支）

  index.min.json            旧格式索引（首字符是 '['），repo.json + 老客户端用
  repo.json                 仓库元信息 + 签名指纹（旧格式路径需要）

### 客户端里怎么加

| 客户端 | 路径 |
| --- | --- |
| Mihon | 设置 → 浏览 → 扩展 → 右上角「扩展仓库」→ 添加 |
| Komikku | 浏览 → 扩展 → 右上角菜单 → 扩展仓库 → 添加 |
| TachiManga | 设置 → 浏览 → 扩展 → 扩展仓库（同名入口） |

地址（任选一个，必须**以 `/index.min.json` 结尾**）：

```
https://raw.githubusercontent.com/TianYuuu/wnacg-extension/repo/index.pb       ← 新版客户端（Tachimanga / Mihon 0.16+）
https://raw.githubusercontent.com/TianYuuu/wnacg-extension/repo/index.min.json  ← 旧格式，兼容老客户端
https://cdn.jsdelivr.net/gh/TianYuuu/wnacg-extension@repo/index.pb              ← GitHub 直连不畅时用
```

Mihon 的仓库解析逻辑（`ExtensionStoreService.fetchStore`）会先看首字符：`[` → 旧格式，要求 URL 以
`/index.min.json` 结尾，随后改读同目录的 `repo.json` 拿名字和签名指纹；APK 地址固定为
`<仓库根>/apk/<apk 文件名>`，图标为 `<仓库根>/icon/<包名>.png`。这套目录结构就是按它摆的。

### 发新版的完整流程

1. 改代码 → 在上游工作区 `git diff > patch/wnacg.diff`；
2. `build.gradle.kts` 里 `versionCode` 加一（现在 101 → 写成 102 就是 `1.6.102`）；
3. `build/build.sh` → 自动更新 `apk/`、`icon/`、`index.min.json`；
4. 提交并推 `repo` 分支；客户端下拉刷新扩展列表就能看到更新。

### 三个坑

1. **别改 `source { name = "紳士漫畫" }`**。源 id 由它算出来，一改收藏立刻失联。
2. **官方 keiyoushi 仓库里也有同包名的 WNACG（1.6.2 / 106002）**。本仓库是 1.6.101 / 106101，版本更高，
   所以不会被它覆盖；但哪天上游把 `libVersion` 提到 1.7（版本号跳到 107xxx），就会反超 —— 那时把
   `versionCode` 加到 900 以上即可（上限 999）。
3. **签名 key 不进仓库**。`wnacg-custom.jks` 自己保存，换 key 只能卸载重装；
   `repo.json` 里的 `signingKeyFingerprint` 必须永远等于 APK 的实际签名（脚本会保持一致）。

## 十二、Tachimanga 的 VerifyError（1.6.101 已修）

报错长这样：

```
java.lang.VerifyError: JVMVRFY021
  class=k, method=a(Lk;)Lokhttp3/OkHttpClient;, pc=17
```

`class=k` 就是根因：keiyoushi 的 release 构建默认 `isMinifyEnabled = true`，R8 把整个扩展压成了一串单字母类
（`La;`…`Lk;`），还做了激进优化。Mihon / Komikku 跑在自己的 ART 上没问题，但 Tachimanga 的字节码校验器
不接受这种被优化过的字节码，于是在加载时直接拒绝。

修法：在模块的 `build.gradle.kts` 里覆盖掉插件的默认配置。

```kotlin
android {
    buildTypes {
        named("release") {
            isMinifyEnabled = false
            isShrinkResources = false
        }
    }
}
```

代价与验证：

| 项目 | 混淆版 1.6.100 | 不混淆 1.6.101 |
| --- | --- | --- |
| APK 大小 | 68 KB | 189 KB |
| dex 里的单字母类 | 26 个（`La;`…`Lk;`） | 0 个 |
| `WNACG` 类名 | 被改写成 `Lk;` | 保留完整路径 |
| 签名 | `596be49f…e27c` | 同上（同一个 key） |

功能完全不变，Mihon / Komikku 上一样能用；只是体积大了点，换来的是任何校验器都能读懂。

> 如果哪天又要开混淆（比如嫌体积），记得 Tachimanga 会再次报 `JVMVRFY021`。
